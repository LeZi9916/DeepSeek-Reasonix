修正上下文占用与压缩阈值的几处统计问题，并让自动压缩阈值可调。

## 新增

- 上下文维护面板新增自动压缩阈值滑块，按模型窗口比例调整（10%–99%），松手后保存并重建运行时；新增 `POST /compaction/ratio` 接口 (d71a8df64)

## 修复

- 自动整理阈值不再只能靠改配置文件调整；滑块拖动只预览，松手才提交一次，保存后立即显示新的整理点 (d71a8df64)
- 上下文图例的百分比与上方的占用数字改用同一分母，不再出现「占用 28% 而图例合计 100%」的互相矛盾 (6588af9b3)
- 系统提示与工具定义等固定内容在对话增长时不再改变占比，此前它们会跟着整段对话的文字构成被重新计价 (2488ef84e)
- 折叠摘要不再被计入「你的输入」，改归入系统侧 (7fe1940fb)
- 模型连续输出工具调用时，速度读数不再归零；调用参数的流出也计入吞吐 (bda549f2e)
- 同一会话继续发消息时，上下文面板不再偶发清空后过几轮才恢复 (a0d7b26f4)
- 覆盖安装时不再报「无法关闭 Reasonix」：关闭窗口后内核会立即退出，不再等满后台任务的收尾宽限期

Fixes several problems in how context usage and the compaction threshold were reported, and makes the threshold adjustable.

## New

- The context-maintenance panel now offers the automatic fold threshold as a slider over the model window (10%–99%); releasing it saves and rebuilds the runtime. New `POST /compaction/ratio` endpoint (d71a8df64)

## Fixed

- The automatic fold threshold no longer has to be changed by editing the config file; dragging previews, releasing saves once, and the new fold point appears immediately (d71a8df64)
- The context legend's percentages and the usage figure above it now share one denominator, so a session can no longer read "28% used" above a legend adding to 100% (6588af9b3)
- Fixed-size parts of the prompt — the system prompt and the tool catalogue — no longer change their share as the conversation grows; they used to be re-priced with the transcript's own text mix (2488ef84e)
- A fold digest is no longer counted as what you typed; it is measured on the system side (7fe1940fb)
- The throughput reading no longer drops to zero while the model streams a run of tool calls; the arguments count as output too (bda549f2e)
- Continuing a conversation no longer blanks the context panel for a round or three before it recovers (a0d7b26f4)
- Installing over an existing copy no longer reports "cannot close Reasonix": closing the window now ends the kernel immediately instead of waiting out the grace given to finishing background jobs
